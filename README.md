# TotemNexus

TotemNexus 是 Totem 系列的 Space Unit、好友、地圖、安全傳送、死亡節點
與分散出生點模組。所有座標、權限、成本與安全落點都由 Server 重新
驗證，Client 只顯示經過篩選的資訊。

目前開發版本為 **0.3.21**，需要 TotemCore **0.7.20 以上、0.8.0 以下**。

## 安裝

Client 與 Server 都放入：

1. Fabric API `0.154.2+26.2`
2. TotemCore `>=0.7.21 <0.8.0`
3. TotemNexus `0.3.21`

| 項目 | 需求 |
| --- | --- |
| Minecraft | 26.2 |
| Fabric Loader | 0.19.3+ |
| Java | 25+ |
| 必要 Totem 模組 | `totem-core >=0.7.21 <0.8.0` |
| 選配 | TotemRemnant（死亡背包 ↔ Death Node 整合） |

Nexus standalone 不要求舊整合包、Remnant 或 Discord Bridge。舊整合 JAR
不應再與獨立 TotemNexus 並用。

- 擴圖保留原有已知地形；新探索外圈可直接採集細節，不再依賴祖先地圖。只有粗圖的舊區域須重新到訪才能補細；採集不強制載入區塊。

## 近距離救援與隨身傳送

需要 TotemCore 0.7.19 以上；Nexus 0.3.19 與 Remnant 0.2.24 共同提供移動背包追蹤。

- 羅盤、回生羅盤與 Nexus 地圖點擊磁石時以該磁石為來源；直接使用而未點擊磁石時，以玩家當前位置為來源。陣外穩定度較低；實際建成的傳送陣提供加成。
- 死亡落點跟隨背包目前位置，優先相距 2～4 格，最多水平 6 格、垂直 3 格，並驗證短途可步行抵達。沒有安全落點就取消且不扣費。
- Nexus 單一「虛化」效果整合虛弱 I、夜視、隱形、抗性 I。成功拾取目標背包後 3 秒解除。

## 世界規則

Nexus 的「分散安全重生點」與「傳送陣擴張模式」現在會集中顯示在
Minecraft 原生世界規則介面的「圖騰世界規則」分類，名稱、說明與擴張模式
選項皆有繁體中文。新世界使用 canonical `totem:nexus/*` 規則；遷移層會
讀取舊規則的非預設值並寫入 canonical 規則。

0.3.11 修正原版遊戲內「世界規則」畫面會拒絕 `local`／`centered` 值、使
「傳送陣擴張模式」看似沒有儲存的問題。新版同時接受介面使用的小寫值與既有
世界存檔使用的大寫列舉名稱，因此不需要重設規則，也不會破壞舊世界。

## 遊戲內 Totem 手冊

手持普通書對磁石按右鍵，可取得原版成書形式的 `Totem 手冊`。內容會
整合所有已安裝 Totem 模組的教學章節；若另一手已有手冊，只刷新內容而
不消耗普通書。兩手各持一本系統生成的手冊時，對磁石使用會保留主動手的
一本並合併另一手。0.2.3 以前生成的 `Nexus Teleport Manual` 必須符合
完整舊版簽章，並對磁石使用一次後才會升級，不會誤改玩家自行撰寫的書。

## 快速開始

### 1. 註冊與綁定磁石

在磁石上使用普通羅盤、回生羅盤、普通書，或使用空白地圖，即可開始
Server 權威的註冊／綁定流程。普通書的操作特別區分為：

- **普通右鍵**：取得或刷新 Totem 手冊，不觸發 Nexus。
- **蹲下＋右鍵**：註冊、綁定或開啟 Nexus 管理。

Server 會建立私有 `LODESTONE` Space Unit，保存維度、座標、Owner、狀態與
結構快照。物品只存 **Space Unit UUID 與資料版本**，不存玩家 UUID 或任何
權限。每次管理、好友、探索或地圖傳送動作，Server 都會用目前登入玩家的
UUID，重新對照 Server 端的 Owner、Administrator、Allowed 與可見性資料。複製或
偽造物品不會獲得角色或權限。

生存模式若輸入物品有堆疊，只拆出 **1 件**保留原有 components 的綁定副本；
創造模式不改動原堆疊，另給 1 件綁定副本。已綁定到同一 Space Unit 時不會
再拆分或複製。普通羅盤仍保留原版磁石追蹤，回生羅盤與書本也保留原生行為。

### 2. 探索磁石

手持已綁定的介面物品左鍵已註冊磁石。只有親自到達、有查看權限且節點仍有效
時，該節點才會加入玩家自己的永久探索資料。

### 3. 建立 Nexus 地圖

手持空白地圖對有權限的磁石使用時，Server 會建立一個新的原版 `MapId`，
以該磁石的精確 X/Z 為中心，再回傳已綁定的 Nexus 已填充地圖。任意現有的
已填充地圖不能後補或偽造成 Nexus 地圖。

使用紙張擴張 Nexus 地圖時，中心永遠保留在原磁石，不會改成玩家位置。
如果錨點磁石消失、所在 chunk 未載入、Space Unit 停用或資料不一致，擴張會
拒絕且不消耗輸入，也不會強制載入 chunk。已有的有效地圖仍可閱讀；原版玻璃板
鎖定會保留像素、裝飾與 Nexus 綁定登錄。複製同一 `MapId` 的地圖仍指向同一張
有效 Nexus 地圖。

### 4. 開啟介面與傳送

- 已綁定的普通羅盤：開啟可搜尋、排序與捲動的**目的地清單**，不顯示地圖；選取清單項目後可查看 Server 報價並傳送。
- 已綁定的回生羅盤：與普通羅盤共用目的地清單及一般磁石傳送，另提供自己的死亡節點救援加成。
- 已綁定的普通書：開啟 **management-only** 畫面，不顯示地圖、目的地或傳送按鈕。
- 有效 Nexus 已填充地圖（包含更新前已建立且綁定仍有效的地圖）：使用原版地圖像素與原版渲染路徑，並可傳送。
- 地圖只顯示相同維度、地圖覆蓋內，且 Server 判定該玩家可見的 active persistent
  Space Units；須該位置的原版地圖像素已實際繪製，但不要求玩家 discovery；每個標記顯示節點名稱。空白舊名稱會使用「未命名 Nexus」。
- 只加入目前在線且存活的雙向好友玩家目標，僅顯示粗略座標與距離；地圖同時要求實際位置與粗略標記位於已繪製範圍。不會加入無關玩家或地圖外邊緣箭頭。
- 地圖畫面不提供目的地清單；直接點擊地圖上的 Nexus 標記選點，查看 Server 報價，再按「傳送」建立倒數 session。
- 地圖縮放改為 `1×`、`2×`、`4×`、`8×`、`16×` 的歷史細節層級：目前 MapId 永遠是完整粗略底圖，若這張 Nexus 地圖曾經由更高解析度的舊 MapId 合法 SCALE 而來，放大時會在對應區域恢復那些原版地圖像素，最多到 vanilla scale 0；沒有可證明的舊 MapId 就不會憑空生成細節。滑鼠滾輪與 `+`／`-` 控制縮放，按住左鍵拖曳或 `Shift`＋方向鍵平移，拖曳不會誤選標記。
- 擁有者在同維度且位於目前地圖覆蓋內時，畫面會以原版玩家圖示即時顯示自己的位置與朝向；這個 marker 只存在於當下 Screen，不寫入 `MapItemSavedData`、物品或 Nexus SavedData。Observer 不會拿觀察者自己的座標冒充被觀察者位置。

## 介面物品

| 物品 | 能力 |
| --- | --- |
| 普通羅盤 | 可註冊、綁定、探索、好友與管理；以清單選目的地並傳送，不顯示地圖 |
| 回生羅盤 | 普通羅盤全部能力；前往自己的有效死亡背包附近時提供虛化；無地圖 canvas |
| 普通書 | 正常右鍵磁石取得手冊，蹲下右鍵磁石才註冊／綁定；可探索、好友與管理；management-only，無地圖或傳送按鈕 |
| 有效 Nexus 已填充地圖 | 由空白地圖在授權磁石上建立；舊版已發出的有效綁定仍可用；只以原版地圖上的 Nexus 標記選點並傳送，沒有目的地清單；目標在覆蓋內時降低食物與偏差 |

空白地圖只是磁石上的地圖建立輸入，不是可直接開啟的持久介面。倒數期間必須
持續在原使用手持有完全相同的介面類型、綁定與地圖 `MapId`。

安裝 TotemRemnant 時，不必先成功傳送：死亡前會自動掃描玩家身上的有效
傳送介面，依「主手 → 副手 → 其餘快捷列 → 主物品欄」保留第一件，讓玩家
重生後仍能透過正常 Nexus 成本與安全規則前往死亡節點或其他目標。每次只
保留一件，不掃描背包等巢狀容器；空白地圖與帶消失行為的物品不符合資格。
舊版成功傳送標記會保留以維持相容，但不再是死亡保留的前置條件。

### 羅盤來源與地圖錨點

普通羅盤與回生羅盤只列出自己已實際探索且目前有權限的磁石目的地，預設依本次來源距離由近到遠，最愛不會插隊；可使用既有排序控制切換排序。兩者皆可對其他授權磁石右鍵轉綁。生存單件原地改綁；堆疊拆一件，創造模式另給副本，保留原版 components。

Nexus Map 的原始綁定識別 map anchor、MapId、地圖中心及擴張中心。羅盤與地圖右鍵點擊磁石時以該磁石為來源；未點擊磁石而直接開啟時，以玩家目前位置出發，這條可攜路徑不要求距磁石 8 格。陣外來源穩定度為 0.6；在有權限且符合介面可見條件的已建成傳送陣內，加上最多 0.35 × 陣體共鳴，並套用該陣材料能力。範圍由實際識別的結構方塊邊界與其上方兩格步行空間決定。

地圖目的地仍須在實際繪製的像素範圍內，且通過權限、手持綁定、成本、路線預約與安全落點檢查。來源變動不改寫 MapId、anchor、center 或地圖資料。書本管理、校準與維護仍須在磁石附近。

### 死亡背包與虛化

兩種羅盤與 Nexus 地圖實際完成前往自己的有效死亡背包後，都會得到 Nexus 的 `totem-nexus:phasing`（虛化）。目的地追蹤實際綁定背包 UUID 的位置，包括漂移與維度變更；不會在背包找不到時傳回原始死亡點。

- 優先相距 2～4 格，水平最多 6 格、垂直最多 3 格；最多步行 10 格可到拾取範圍，不能隔著封閉牆角或樓層。
- 虛化只有一個效果圖示，包含虛弱 I、夜視、隱形與抗性 I；不提供穿牆或釀造配方。
- 成功將此次目標背包拾入物品欄後，開始不可重置的 3 秒倒數。搜尋期間沒有 60 秒上限；其他背包不觸發倒數。
- 每次合法完成自己的死亡傳送都可獲得效果；不再消耗每節點的一次性資格。
- 攻擊、PvP、攻擊性投射物、另一趟傳送、節點失效、背包銷毀、死亡或登出立即取消。區塊卸載不算銷毀，喝牛奶解除後不會自動補回。
- 原有的虛弱、夜視、隱形與抗性藥水持續正常計時，不被虛化刪除或取代。

## 石碑結構與材料

Nexus 提供兩套 Server 權威的傳送陣擴張算法，可由世界規則切換：

```text
/gamerule totem:nexus/teleport_array_expansion_mode local
/gamerule totem:nexus/teleport_array_expansion_mode centered
```

預設 `local` 完全保留原本的不規則局部路徑：從磁石周圍一格、排除中心的
`3×3×3`（26 格）開始，帶有正掃描擴張值的已掃描材料，會從**自身位置**
繼續展開掃描。因此範圍沿玩家實際擺放的材料鏈延伸，不會自動補成完整外殼。

`centered` 則始終以磁石為中心。初始半徑是 1；若已掃描到的擴張材料離磁石
Chebyshev 距離為 `d`、自身有效擴張半徑為 `r`，新半徑取
`max(目前半徑, d + r)`，最高 5。每次增加後都掃描以磁石為中心的完整立方，
反覆計算直到半徑不再增加。同一層有多個材料時只取最大值，不會把半徑相加。

兩種模式都只讀取已載入區塊，絕不為掃描強制載入 chunk，且離磁石最遠不會
超過 5 格。切換規則時會立即重掃已載入的 active 磁石；未載入磁石維持不強載，
等到合法存取且 chunk 已載入時才更新。傳送報價、磨損／維修、材料快照以及
傳送陣／可建造位置顯示全部共用同一套目前模式的掃描結果。

Tier 改由材料提供的有效容量決定：

| 條件 | Tier |
| --- | ---: |
| 少於 8 容量 | 0 |
| 至少 8 容量 | 1 |
| 至少 24 容量 | 2 |

入門配置是在磁石同高度對稱放置一圈 8 個有效方塊：

```text
S S S
S L S
S S S
```

`L` 是磁石；`S` 是能提供容量的結構材料。石磚類、加工深板岩類、下界磚類、拋光黑石類、
凝灰岩、黑曜石、哭泣黑曜石、銅、金屬、礦物、原礦塊與礦石皆有不同的正負取捨；
銅還會受形狀、氧化與上蠟狀態影響。Space Unit 地圖的「材料」頁才是目前資料包數值的權威來源；
資料包作者可參考 [材料 profile 文件](docs/teleport-array-material-profiles.md)。

在來源磁石附近開啟 Space Unit 地圖並切到「材料」，可分別切換「顯示傳送陣」
與「顯示可建造位置」，兩者可以單獨或同時開啟。關閉地圖畫面不會關閉顯示；
同一個 Client session 內會約每秒向 Server 要求一次 loaded-only 權威刷新，且
完整位置只在結果改變時重傳。青色是來源磁石與所有已計入方塊合併後的最外圍
框線；相鄰方塊之間不再畫共享邊或平面格線。較低干擾且受牆面遮擋的綠色，則
是所有已到達、目前不是結構材料且可被放置方塊取代的位置所形成的另一組最外
圍框線。兩組會各自保留不規則或分離的真實形狀，不會用一個大長方體包住空白
區域。放入材料後該格會移到已計入集合；若放入擴張材料，新到達空位也會隨刷
新出現。首次開啟仍必須手持已綁定的合法
介面；開啟成功後即可收起地圖、換成建材施工，顯示會持續動態更新。再次按下
各自按鈕才隱藏該類別。

顯示適用於材料頁選取且通過伺服器驗證的附近磁石，不會改變傳送來源，也不會顯示遠端目的地、未載入區塊或未被延伸
路徑連到的位置。離開 8 格安全範圍、切換維度／世界、斷線、磁石或權限失效時
會安全清除，回到附近後需要手動再次開啟。

內建 profile 的常用正向選擇如下；資料包可改值，所以遊戲中的「材料」頁
仍是最終依據：

| 目的 | 主要預設材料 |
| --- | --- |
| 結構容量／階級 | 多數材料 `+1`；非裂紋深板岩／拋光黑石家族、鐵、鑽石 `+2`；裂紋變體仍為 `+1`；獄髓 `+3` |
| 掃描擴張 | 新銅燈、鐵、紫水晶、紅石 `+1`；鑽石、獄髓 `+2` |
| 到達精度 | 鏨製石磚／深板岩／下界磚、切製銅、紫水晶、鑽石、青金 `+2`；多種精煉材料與青金／紅石／鑽石／綠寶石／下界石英礦 `+1` |
| 目標鎖定 | 鏨製銅、鏨製黑石 `+3`；鏨製石磚／深板岩／下界磚、青金 `+2` |
| 穩定／安全／耐久 | 獄髓最高；鑽石、深板岩磚、拋光黑石磚、遠古遺骸是主要正向選擇 |
| 抗干擾 | 青苔石磚、拋光黑石 `+2`；鏨製黑石、獄髓、遠古遺骸 `+1` |
| 速度／冷卻 | 紅石提供最高速度；金、下界磚、銅柵格偏速度，銅燈、金、紅石偏冷卻 |
| 食物／負載／維護 | 金與綠寶石省食物；銅燈、鐵、獄髓提高負載；拋光深板岩／黑石與綠寶石提高維護效率 |
| 跨維度催化 | 紫水晶方塊預設每個 `+1` 催化單位 |

新增的三種基礎材料保留明確定位：凝灰岩是便宜、容易維護但穩定度較低的
Overworld 基線；黑曜石提供高穩定、抗磨損與抗干擾，但相位慢且難維護；
哭泣黑曜石提高到達精度、目標鎖定與 Nether 親和，代價是較差的安全、抗干擾
與相位速度。三者都不提供掃描擴張，避免成為全能材料。

一般煤、鐵、銅、金、青金、紅石、鑽石、綠寶石及下界礦石 profile 通常會讓
掃描擴張 `-1`，並伴隨穩定、抗干擾、耐久或維護等負面代價；不要把礦石
當成純粹的擴張材料。

跨維度傳送要求兩端固定磁石至少 Tier 1。

## 傳送成本與安全

- 同維度基礎食物成本約每 384 格增加 1 點，最高 20。
- 優先扣飽和度，再扣飢餓值，最後才消耗物品欄中的安全食物。
- 跨維度另外消耗紫水晶碎片；來源與目標的催化單位合計每 4 單位折抵 1，
  最終至少消耗 1。紫水晶方塊預設提供 1 單位，資料包可調整或提供負值。
- 創造模式不消耗資源。
- 穩定度低於 0.2、權限失效或沒有安全落點時不會傳送。

準備時間為 40–300 ticks。受傷、死亡、移動超過 4 格、切換維度、
換掉介面物品、來源／目標失效、資源不足或好友解除都會在扣款前取消。
材料還會由 Server 計入穩定、干擾、漂移、到達傷害、損耗、食物、準備時間、
冷卻、路線負載與維護成本，所有最終數值皆有安全上下限。
安全落點要求腳部與頭部無碰撞／流體、有可站立地板、位於世界邊界內，
並避開岩漿、火、營火、仙人掌、岩漿塊與細雪。

## 好友與玩家目標

- 手持任一有效綁定介面右鍵玩家，可送出或接受好友邀請。
- 好友關係可用於好友管理、`FRIENDS` 可見性，以及 Server 端的存取授權。
- 普通／回生羅盤會列出在線且存活的雙向好友，可選取並傳送；離線、死亡或解除好友時移除目標，開始與完成傳送時都會重驗。
- 好友只顯示 64 格水平／16 格垂直網格的粗略位置，以及 64 格級距的距離；不發送精確座標。Nexus 地圖另要求實際位置與粗略標記都位於已繪製範圍。

## 死亡節點

同時安裝 TotemRemnant 時，死亡背包可建立綁定的 `DEATH` Space Unit。
0.2.0 保存 Death Node → backpack Entity UUID 的反向連結，因此管理診斷
不需載入 chunk 搜尋實體。死亡背包完全回收後，對應節點會停用並從
一般地圖隱藏。

所有遊戲內玩家都可開啟：

```text
/totem deathnodes
/totem deathpoints
```

一般玩家只會收到自己擁有的死亡節點，可選取單一節點並在 30 秒內二次
確認後永久刪除傳送點；即使 Client 偽造 Owner 或節點 UUID，Server 仍會
以登入玩家 UUID 重新驗證。刪除不會移動或刪除留在世界中的死亡背包。

管理員使用同一介面時仍可依 Owner／維度／狀態／時間篩選、安全傳送、
先停用後永久刪除，以及執行需要二次確認的批次操作。Console 不能開啟 GUI。

## 跨模組事件

Nexus 透過 TotemCore event bus 發布公開 Space Unit 更新、死亡背包回收
與管理稽核摘要。TotemDiscordBridge 可自行訂閱這些型別事件；Nexus
不直接依賴 Discord，也不再呼叫反射 adapter。沒有任何
subscriber 時，Nexus standalone 行為不受影響。

## 舊世界相容

Nexus 的遷移層只讀取四組舊 `deadrecall` SavedData keys、舊 NBT 綁定與舊
世界規則，並立即寫入 canonical ID。Payload、指令與資料包只使用新的
`totem:nexus/*` ID。遷移覆蓋 Space Unit、探索／最愛、好友、分散出生點與
死亡背包反向綁定。

### 地圖記錄與載入行為

- 主手、雙手與副手的 Nexus 地圖會顯示持圖者位置與方向；此標記不寫入共享地圖或物品展示框。
- 節點是否可見仍受權限限制，好友關係與收藏仍屬個人資料。轉交地圖不會轉交私人存取權。
- 擴圖與鎖圖會保存當時的細節快照；之後修改來源地圖，不會回寫衍生圖。舊鎖圖僅保留可證明的凍結記錄。
- 新細節保存於世界的 `totem:nexus_map_detail_v1` SavedData，索引與色彩頁同檔；不要單獨刪除它。主圖仍為原版 MapId 資料。
- 每 tick 全服最多檢查 2048 個候選地形欄、每 MapId 最多 128 個；每觀看者最多同步 20 個相交圖層（含最多 4 個歷史圖層），地圖佇列每 tick 不超過 32 KiB。客戶端快取最多 64 個細節頁。
- 目前每張地圖最多 293 頁，全世界最多 8192 頁（原始色彩約 128 MiB）。達上限時保留現有資料並回退主圖，不會刪除舊頁；首版不自動回收頁面。
- 磁石目的地尚未載入時，開始傳送才暫時載入並重新驗證。載入與落點搜尋共用 200 tick 預算，準備倒數另計；費用或條件改變會取消，請重新選取目的地。失敗會恢復本次扣除的食物、紫水晶與飢餓／飽和值，票券也會釋放。

地圖回歸可用 `-PnexusTestFocus=map` 執行既有 GameTest runners；未指定時 CI 執行完整清單。正式環境另用 `runProductionClientGameTest` 驗證實際 JAR。
