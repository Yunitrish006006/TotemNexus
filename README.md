# TotemNexus

TotemNexus 是 Totem 系列的 Space Unit、好友、地圖、安全傳送、死亡節點
與分散出生點模組。所有座標、權限、成本與安全落點都由 Server 重新
驗證，Client 只顯示經過篩選的資訊。

目前模組版本為 **0.3.9**，需要 TotemCore **0.7.14 以上、0.8.0 以下**。

## 安裝

Client 與 Server 都放入：

1. Fabric API `0.154.2+26.2`
2. TotemCore `>=0.7.14 <0.8.0`
3. TotemNexus `0.3.9`

| 項目 | 需求 |
| --- | --- |
| Minecraft | 26.2 |
| Fabric Loader | 0.19.3+ |
| Java | 25+ |
| 必要 Totem 模組 | `totem-core >=0.7.14 <0.8.0` |
| 選配 | TotemRemnant（死亡背包 ↔ Death Node 整合） |

Nexus standalone 不要求 DeadRecall、Remnant 或 Discord Bridge。使用
DeadRecall 2.4.11 整合 JAR 時不要再安裝獨立 TotemNexus。

## 遊戲內 Totem 手冊

手持普通書對磁石按右鍵，可取得原版成書形式的 `Totem 手冊`。內容會
整合所有已安裝 Totem 模組的教學章節；若另一手已有手冊，只刷新內容而
不消耗普通書。兩手各持一本系統生成的手冊時，對磁石使用會保留主動手的
一本並合併另一手。0.2.3 以前生成的 `Nexus Teleport Manual` 必須符合
完整舊版簽章，並對磁石使用一次後才會升級，不會誤改玩家自行撰寫的書。

## 快速開始

### 1. 註冊與綁定磁石

在磁石上使用普通羅盤、回生羅盤、普通書，或使用空白地圖，即可開始
Server 權威的註冊／綁定流程。普通書的操作特別區分為：

- **普通右鍵**：取得或刷新 Totem 手冊，不觸發 Nexus。
- **蹲下＋右鍵**：註冊、綁定或開啟 Nexus 管理。

Server 會建立私有 `LODESTONE` Space Unit，保存維度、座標、Owner、狀態與
結構快照。物品只存 **Space Unit UUID 與資料版本**，不存玩家 UUID 或任何
權限。每次管理、好友、探索或地圖傳送動作，Server 都會用目前登入玩家的
UUID，重新對照 Server 端的 Owner、Administrator、Allowed 與可見性資料。複製或
偽造物品不會獲得角色或權限。

生存模式若輸入物品有堆疊，只拆出 **1 件**保留原有 components 的綁定副本；
創造模式不改動原堆疊，另給 1 件綁定副本。已綁定到同一 Space Unit 時不會
再拆分或複製。普通羅盤仍保留原版磁石追蹤，回生羅盤與書本也保留原生行為。

### 2. 探索磁石

手持已綁定的介面物品左鍵已註冊磁石。只有親自到達、有查看權限且節點仍有效
時，該節點才會加入玩家自己的永久探索資料。

### 3. 建立 Nexus 地圖

手持空白地圖對有權限的磁石使用時，Server 會建立一個新的原版 `MapId`，
以該磁石的精確 X/Z 為中心，再回傳已綁定的 Nexus 已填充地圖。任意現有的
已填充地圖不能後補或偽造成 Nexus 地圖。

使用紙張擴張 Nexus 地圖時，中心永遠保留在原磁石，不會改成玩家位置。
如果錨點磁石消失、所在 chunk 未載入、Space Unit 停用或資料不一致，擴張會
拒絕且不消耗輸入，也不會強制載入 chunk。已有的有效地圖仍可閱讀；原版玻璃板
鎖定會保留像素、裝飾與 Nexus 綁定登錄。複製同一 `MapId` 的地圖仍指向同一張
有效 Nexus 地圖。

### 4. 開啟介面與傳送

- 已綁定的普通羅盤、回生羅盤與書本：開啟 **management-only** 畫面，不顯示地圖、目標或傳送按鈕。
- 有效 Nexus 已填充地圖：使用原版地圖像素與原版渲染路徑。
- 地圖只顯示相同維度、地圖覆蓋內，且 Server 判定該玩家可見的 active persistent
  Space Units；每個標記顯示節點名稱。空白舊名稱會使用「未命名 Nexus」。
- 不會合成線上玩家的 `PLAYER` 座標，也不會對地圖外目標顯示邊緣箭頭。
- 選取地圖上的節點後查看 Server 報價，再按「傳送」建立倒數 session。

## 介面物品

| 物品 | 能力 |
| --- | --- |
| 普通羅盤 | 可註冊、綁定、探索、好友與管理；management-only，無地圖或傳送按鈕 |
| 回生羅盤 | 可註冊、綁定、探索、好友與管理；management-only，無地圖或傳送按鈕 |
| 普通書 | 正常右鍵磁石取得手冊，蹲下右鍵磁石才註冊／綁定；可探索、好友與管理；management-only，無地圖或傳送按鈕 |
| 有效 Nexus 已填充地圖 | 由空白地圖在授權磁石上建立；支援全部管理並顯示原版地圖；目標在覆蓋內時降低食物與偏差 |

空白地圖只是磁石上的地圖建立輸入，不是可直接開啟的持久介面。倒數期間必須
持續在原使用手持有完全相同的介面類型、綁定與地圖 `MapId`。

安裝 TotemRemnant 時，不必先成功傳送：死亡前會自動掃描玩家身上的有效
傳送介面，依「主手 → 副手 → 其餘快捷列 → 主物品欄」保留第一件，讓玩家
重生後仍能透過正常 Nexus 成本與安全規則前往死亡節點或其他目標。每次只
保留一件，不掃描背包等巢狀容器；空白地圖與帶消失行為的物品不符合資格。
舊版成功傳送標記會保留以維持相容，但不再是死亡保留的前置條件。

## 石碑結構與材料

Nexus 提供兩套 Server 權威的傳送陣擴張算法，可由世界規則切換：

```text
/gamerule deadrecall:teleport_array_expansion_mode local
/gamerule deadrecall:teleport_array_expansion_mode centered
```

預設 `local` 完全保留原本的不規則局部路徑：從磁石周圍一格、排除中心的
`3×3×3`（26 格）開始，帶有正掃描擴張值的已掃描材料，會從**自身位置**
繼續展開掃描。因此範圍沿玩家實際擺放的材料鏈延伸，不會自動補成完整外殼。

`centered` 則始終以磁石為中心。初始半徑是 1；若已掃描到的擴張材料離磁石
Chebyshev 距離為 `d`、自身有效擴張半徑為 `r`，新半徑取
`max(目前半徑, d + r)`，最高 5。每次增加後都掃描以磁石為中心的完整立方，
反覆計算直到半徑不再增加。同一層有多個材料時只取最大值，不會把半徑相加。

兩種模式都只讀取已載入區塊，絕不為掃描強制載入 chunk，且離磁石最遠不會
超過 5 格。切換規則時會立即重掃已載入的 active 磁石；未載入磁石維持不強載，
等到合法存取且 chunk 已載入時才更新。傳送報價、磨損／維修、材料快照以及
傳送陣／可建造位置顯示全部共用同一套目前模式的掃描結果。

Tier 改由材料提供的有效容量決定：

| 條件 | Tier |
| --- | ---: |
| 少於 8 容量 | 0 |
| 至少 8 容量 | 1 |
| 至少 24 容量 | 2 |

入門配置是在磁石同高度對稱放置一圈 8 個有效方塊：

```text
S S S
S L S
S S S
```

`L` 是磁石；`S` 是能提供容量的結構材料。石磚類、加工深板岩類、下界磚類、拋光黑石類、
凝灰岩、黑曜石、哭泣黑曜石、銅、金屬、礦物、原礦塊與礦石皆有不同的正負取捨；
銅還會受形狀、氧化與上蠟狀態影響。Space Unit 地圖的「材料」頁才是目前資料包數值的權威來源；
資料包作者可參考 [材料 profile 文件](docs/teleport-array-material-profiles.md)。

在來源磁石附近開啟 Space Unit 地圖並切到「材料」，可分別切換「顯示傳送陣」
與「顯示可建造位置」，兩者可以單獨或同時開啟。關閉地圖畫面不會關閉顯示；
同一個 Client session 內會約每秒向 Server 要求一次 loaded-only 權威刷新，且
完整位置只在結果改變時重傳。青色為一般計入方塊、金色為會繼續延伸掃描的
材料、紫色為來源磁石；較低干擾且受牆面遮擋的綠色，則是掃描已到達、目前
不是結構材料且可被放置方塊取代的位置。放入材料後該格會移到已計入集合；若
放入擴張材料，新到達空位也會隨刷新出現。首次開啟仍必須手持已綁定的合法
介面；開啟成功後即可收起地圖、換成建材施工，顯示會持續動態更新。再次按下
各自按鈕才隱藏該類別。

顯示只適用於目前地圖的本地來源，不會顯示遠端目的地、未載入區塊或未被延伸
路徑連到的位置。離開 8 格安全範圍、切換維度／世界、斷線、磁石或權限失效時
會安全清除，回到附近後需要手動再次開啟。

內建 profile 的常用正向選擇如下；資料包可改值，所以遊戲中的「材料」頁
仍是最終依據：

| 目的 | 主要預設材料 |
| --- | --- |
| 結構容量／階級 | 多數材料 `+1`；非裂紋深板岩／拋光黑石家族、鐵、鑽石 `+2`；裂紋變體仍為 `+1`；獄髓 `+3` |
| 掃描擴張 | 新銅燈、鐵、紫水晶、紅石 `+1`；鑽石、獄髓 `+2` |
| 到達精度 | 鏨製石磚／深板岩／下界磚、切製銅、紫水晶、鑽石、青金 `+2`；多種精煉材料與青金／紅石／鑽石／綠寶石／下界石英礦 `+1` |
| 目標鎖定 | 鏨製銅、鏨製黑石 `+3`；鏨製石磚／深板岩／下界磚、青金 `+2` |
| 穩定／安全／耐久 | 獄髓最高；鑽石、深板岩磚、拋光黑石磚、遠古遺骸是主要正向選擇 |
| 抗干擾 | 青苔石磚、拋光黑石 `+2`；鏨製黑石、獄髓、遠古遺骸 `+1` |
| 速度／冷卻 | 紅石提供最高速度；金、下界磚、銅柵格偏速度，銅燈、金、紅石偏冷卻 |
| 食物／負載／維護 | 金與綠寶石省食物；銅燈、鐵、獄髓提高負載；拋光深板岩／黑石與綠寶石提高維護效率 |
| 跨維度催化 | 紫水晶方塊預設每個 `+1` 催化單位 |

新增的三種基礎材料保留明確定位：凝灰岩是便宜、容易維護但穩定度較低的
Overworld 基線；黑曜石提供高穩定、抗磨損與抗干擾，但相位慢且難維護；
哭泣黑曜石提高到達精度、目標鎖定與 Nether 親和，代價是較差的安全、抗干擾
與相位速度。三者都不提供掃描擴張，避免成為全能材料。

一般煤、鐵、銅、金、青金、紅石、鑽石、綠寶石及下界礦石 profile 通常會讓
掃描擴張 `-1`，並伴隨穩定、抗干擾、耐久或維護等負面代價；不要把礦石
當成純粹的擴張材料。

跨維度傳送要求兩端固定磁石至少 Tier 1。

## 傳送成本與安全

- 同維度基礎食物成本約每 384 格增加 1 點，最高 20。
- 優先扣飽和度，再扣飢餓值，最後才消耗物品欄中的安全食物。
- 跨維度另外消耗紫水晶碎片；來源與目標的催化單位合計每 4 單位折抵 1，
  最終至少消耗 1。紫水晶方塊預設提供 1 單位，資料包可調整或提供負值。
- 創造模式不消耗資源。
- 穩定度低於 0.2、權限失效或沒有安全落點時不會傳送。

準備時間為 40–300 ticks。受傷、死亡、移動超過 4 格、切換維度、
換掉介面物品、來源／目標失效、資源不足或好友解除都會在扣款前取消。
材料還會由 Server 計入穩定、干擾、漂移、到達傷害、損耗、食物、準備時間、
冷卻、路線負載與維護成本，所有最終數值皆有安全上下限。

安全落點要求腳部與頭部無碰撞／流體、有可站立地板、位於世界邊界內，
並避開岩漿、火、營火、仙人掌、岩漿塊與細雪。

## 好友與玩家目標

- 手持任一有效綁定介面右鍵玩家，可送出或接受好友邀請。
- 好友關係可用於好友管理、`FRIENDS` 可見性，以及 Server 端的存取授權。
- Nexus 地圖不廣播、傳送或顯示線上玩家位置，也不產生即時 `PLAYER` 點位。
- 地圖只顯示 Server 篩選後的持久 Space Units；好友關係只影響其中哪些節點可見，不暴露好友座標。

## 死亡節點

同時安裝 TotemRemnant 時，死亡背包可建立綁定的 `DEATH` Space Unit。
0.2.0 保存 Death Node → backpack Entity UUID 的反向連結，因此管理診斷
不需載入 chunk 搜尋實體。死亡背包完全回收後，對應節點會停用並從
一般地圖隱藏。

所有遊戲內玩家都可開啟：

```text
/deadrecall deathnodes
/deadrecall deathpoints
```

一般玩家只會收到自己擁有的死亡節點，可選取單一節點並在 30 秒內二次
確認後永久刪除傳送點；即使 Client 偽造 Owner 或節點 UUID，Server 仍會
以登入玩家 UUID 重新驗證。刪除不會移動或刪除留在世界中的死亡背包。

管理員使用同一介面時仍可依 Owner／維度／狀態／時間篩選、安全傳送、
先停用後永久刪除，以及執行需要二次確認的批次操作。Console 不能開啟 GUI。

## 跨模組事件

Nexus 透過 TotemCore event bus 發布公開 Space Unit 更新、死亡背包回收
與管理稽核摘要。TotemDiscordBridge 可自行訂閱這些型別事件；Nexus
不直接依賴 Discord，也不再呼叫 DeadRecall 的反射 adapter。沒有任何
subscriber 時，Nexus standalone 行為不受影響。

## 舊世界相容

Nexus 保留既有的四組 `deadrecall` SavedData keys、payload IDs 與資源
identifiers。0.2.5 保留 0.2.1 已通過的 root authority seed → external migrate → 第二
JVM verify，涵蓋 Space Unit、探索／最愛、好友、分散出生點與死亡背包
反向綁定。
