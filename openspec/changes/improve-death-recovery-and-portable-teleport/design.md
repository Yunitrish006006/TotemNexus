## Context
Production execution is in NexusSpaceUnitAuthority; the extracted resolver/quote seams are also covered but must not be mistaken for the only runtime path. Existing death records persist a backpack entity UUID but target resolution uses the original node position. Remnant owns ItemEntity movement and successful recovery. Existing NexusRecoveryGrace is invisibility-only, recovery-compass-only, once-per-node and capped at 1,200 ticks.

## Decisions
1. **Live backpack authority.** Use the exact node/backpack/owner binding. Remnant reports changed block position/dimension from server entity lifecycle through a compatible Core callback. Nexus retains latest confirmed location; final execution resolves the exact entity after bounded asynchronous route loading. No global entity scan, client coordinates, or silent fallback to original death coordinates. Revalidate drift at safe-landing selection and immediately before movement; restart bounded search or cancel without charging when the target moves outside the accepted neighborhood.
2. **Close and reachable landing.** Prefer safe positions 2–4 horizontal blocks away, never beyond 6 Euclidean horizontal blocks or 3 vertical blocks from the backpack. Prefer direct visibility; otherwise accept a bounded traversable walking route of at most 10 blocks to pickup range, including a corner. Do not accept a nearby column across a sealed wall or on an inaccessible roof. No nearby safe reachable location means a clear failure and no consumed payment; do not widen the search to the old 48-block envelope. A backpack high in the air or in inaccessible terrain is handled by this same rule.
3. **Nexus-owned Phasing.** A real Nexus-registered MobEffect with one visible native status icon; effective Weakness I, Night Vision, Invisibility and Resistance I. Do not remove, replace or shorten effects from potions or other modules. It is not block noclip, immunity, or a new brewing recipe. Successful eligible teleport to one's own bound active death backpack grants the effect for the recovery session regardless of compass-family/map choice. Searching has no fixed 60-second timeout; exact successful recovery changes to a 60-tick suffix. Wrong backpack recovery does nothing. Preserve offensive-action, death, logout, new teleport and invalid-node cancellation; do not leave a permanent effect after a target ceases to exist. Legitimate unloaded chunks alone are not evidence of destruction.
4. **Portable source.** A valid held compass/recovery compass/map can open and start teleport outside an array. The actual server player position is the source for distance/dimension/cost. Existing bindings and destination eligibility are preserved; maps retain immutable registry anchor and MapId. Unloaded distant anchors must not be force-loaded just to open the UI. Revalidate current held item and current inside/outside state at start and completion.
5. **Array bonus footprint.** Derive a bounded footprint from the actual currently recognized structural blocks under the configured LOCAL/CENTERED scanner mode, including usable walking space above the structure floor. Do not substitute an eight-block sphere or the entire maximum scanner envelope when no structure occupies it. Array membership cannot make an otherwise valid field route worse: base source stability is 60%; inside a valid array add up to 35 percentage points according to its effective resonance (cap 95%). Existing destination/distance/dimension factors remain represented, but low field stability alone cannot disable a portable route. Array-only material/catalyst contributions do not apply outside its footprint. All costs remain bounded and cross-dimension payment stays nonzero.
6. **Presentation.** Explain field versus array bonus and Phasing in English/Traditional Chinese handbook and existing native UI. If semantic UI payloads change, version them and retain owner-provided Observer reconstruction, remote cursor and input/packet suppression. New effect icon follows the Totem 16×16 gate.

## Compatibility
Preserve saved node identity, backpack UUID, old world loading, map anchors and existing public effect instances. A default Core location callback keeps older providers source-compatible. Review every actual consumer before shared API edits. Release/version selection is separate from this implementation proposal.

## Validation
Pure tests cover distances, same/different source, array bonus monotonicity, low-stability availability and exact 60-tick suffix. Server GameTests cover floating/moving/backpack dimension changes, unload/reload, target movement during countdown, obstruction/short corner paths, inaccessible destinations without charge, ownership/spoof protection and independent potion preservation. Client tests prove one Phasing icon and actual night vision/invisibility behavior, field/array quote changes and English/Traditional Chinese text. Run Java 25 build, module-present Observer tests/screenshots, three-JVM E2E and production runtime; obtain independent review.

## Approval choices
Default interpretation of “找到” is successful recovery of the exact death backpack, not merely entering its vicinity. If the user chooses a different trigger before approval, update the lifecycle requirement consistently before implementation.
